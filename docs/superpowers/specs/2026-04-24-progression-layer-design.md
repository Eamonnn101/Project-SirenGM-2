# Progression Layer — Artifact + Innate + Destiny + Death + Light Meta

Date: 2026-04-24
Status: Implemented, shipping under v0.4

## Problem

The pacing-discipline tranche of v0.4 made conflicts feel decisive but
left the **run shape** open-ended. There was no build, no
breakthrough, no real death — every save was a flat sequence of
turns until the user lost interest. The play-test ask was: borrow
the *structural feel* of Tale of Immortal (1 artifact + 3 innate
traits at start → stage breakthroughs → 1-of-3 destiny pick per
breakthrough → death → light meta) without porting any
xianxia-specific lore, vocabulary, or numeric system. Mechanics
must be reusable across novel types — wuxia, sci-fi, political
drama, romance — so the same progression layer rides on top of
each ingested pack.

Hard constraints from the user prompt:

- MVP only.
- No xianxia / martial arts / cultivation hardcoding.
- No XP bars.
- No numeric levels.
- Mechanically reusable across novel types.
- Names / flavor / lore fit / wording generated by the LLM from
  the imported novel.
- Compatible with the existing file-driven SirenGM 2 workflow
  (no new CLI, no new top-level dirs).

## Design

### Layer separation

```
genre_packs/universal/systems/   ← mechanic SEEDS (stable, archetype keys)
ingest Stage 0                    ← synthesizes packs/<pack>/progression_rules.md
packs/<pack>/progression_rules.md ← novel-themed instances of the seeds
saves (PlayerState fields)        ← what the player picked this run
saves/<pack>/meta_progress.json   ← per-pack cross-save coverage + counters
```

Universal seeds are stable strings (e.g. `not_meant_to_die`,
`bond_rescue`, `talent`). Novel-themed slugs and display names
vary per pack but always carry the universal archetype key in
their frontmatter, so lint, renderer, and `_progression.py` logic
keep a stable vocabulary.

### Stages (6, narrative)

| index | universal seed label          |
| ----- | ----------------------------- |
| 0     | establish footing             |
| 1     | enter the main conflict       |
| 2     | build influence / resources   |
| 3     | break a key stalemate         |
| 4     | become a major variable       |
| 5     | rewrite fate                  |

Stored as `PlayerState.stage_index: int (0..5)` and
`PlayerState.stage_label: str | None`. Soft rules in
`gm_system_fragment.md`: max 5 advances/run, never on a
non-climactic turn, no double advance, no regression. Per-pack
breakthrough trigger patterns (2–4 per stage) are required in
`progression_rules.md` §2 — grounding the GM's judgment.

### Artifact archetypes (3)

`insight` (reveal/learn) · `bond_rescue` (one-shot survival) ·
`companion` (recruit/dispatch). Picked once at new-game Step 1.5.
Stored as `PlayerState.artifact: PlayerArtifact | None`. Distinct
from `inventory` because the mechanics are special. `bond_rescue`
participates in the survival-trigger precedence flow.

### Innate trait archetypes (5)

`talent` · `survival` · `social` · `resource` · `temperament`.
Picked **3 distinct** at new-game Step 1.6. Immutable for the run.
Stored as `PlayerState.innate_traits: list[Trait]` (length 3).

### Destiny trait seeds (12)

Four families:

- **Survival/escape**: `not_meant_to_die`, `golden_cicada_escape`,
  `last_barrier`.
- **Insight/learning**: `heaven_piercing_eye`, `learn_from_enemy`,
  `breakthrough_instinct`.
- **Desperation/clutch**: `martial_remnant_resolve`, `last_stand`,
  `blood_debt`.
- **Companion/social/info**: `little_shadow`, `timely_ally`,
  `read_the_room`.

At each breakthrough (stages 1..5) the GM offers 3 of the 12 plus
a fixed D fallback (decline; stage advances anyway). Up to 5
destiny picks per run; all archetypes distinct within a run.

### Health ladder + death

5-state narrative ladder (`healthy → hurt → badly_hurt → critical
→ dead`). `critical` requires priority handling on the next turn
but is **not** a 1-turn death timer; consequence timing tracks the
genre.

**Survival-trigger precedence** before death is terminal (locked
order):

1. Artifact `bond_rescue` archetype, unused → fires, marks
   `used: True`, transitions to `critical`.
2. Destiny `not_meant_to_die`, not exhausted → fires, marks
   `exhausted: True`, transitions to `critical`.
3. Destiny `last_barrier`, not exhausted, **only on**
   `critical → dead` → fires, grants one extra buffer turn at
   `critical`.

Implementation in `tools/_progression.py ::
resolve_survival_trigger`. No other MVP trigger prevents death.

Terminal death writes `run_summary.md`, bumps `deaths_count`,
appends a `DeathRecord`, updates `best_stage_index`, merges seen
pools. Clean completion (stage 5 + final beat lands cleanly)
bumps `runs_finished` instead.

### Light meta progression

`saves/<pack>/meta_progress.json` (per-pack, cross-save):

- `seen_*_archetypes` (universal keys) — drives the unseen-first
  draft bias on artifact / innate / destiny menus until ~70%
  coverage. After threshold, free draw.
- `seen_*_slugs` (novel-themed names) — drives flavor variation
  within an archetype across runs.
- `runs_started`, `runs_finished`, `deaths_count`,
  `best_stage_index` — light counters for the HUD and run-end
  block.
- `deaths: list[DeathRecord]` — cause + stage at death.

**Not** a permanent power tree. Every archetype is available on
every run regardless of coverage; the meta only changes which
options surface first.

### Two-layer textual HUD

User explicitly asked for readable/beautiful presentation, not
just a functional data model. Implementation in
`tools/_hud.py`:

- **Layer A** — compact turn HUD at top of `current_scene.md`
  every turn (Unicode box; stage / health / artifact / innate /
  destiny / conflict / goals / threads with warning markers).
- **Layer B** — full build HUD in `player.md` and
  `tools/inspect_save.py` (header box + sections for artifact
  with activation contract, innate traits, destiny traits with
  source_stage + exhausted, light meta summary).
- **Special chat-reply blocks** in
  `genre_packs/universal/prompts/`:
  - `new_game_build_picks.md` (artifact + innate)
  - `breakthrough_pick.md` (destiny)
  - `death_coda.md` (run-end, both death and completion)

zh and en parity throughout. CJK-aware visual width
(`unicodedata.east_asian_width`) keeps box alignment honest in
both languages.

## Settled design decisions

Locked during planning (recorded in
`/Users/eamon/.claude/plans/sirengm-2-v0-4-staged-bunny.md`):

1. Ship under existing **v0.4** label (pacing + progression
   bundled). No v0.5 bump.
2. Meta location: `saves/<pack>/meta_progress.json` (sibling of
   save dirs; survives re-ingest).
3. Innate picks: 3 **distinct archetypes** per run.
4. Breakthrough trigger: GM narrative judgment only (soft rules +
   per-stage patterns from the pack), no hard cooldown.
5. Artifact: exactly one at run start, immutable for MVP.
6. Meta: light but **real** — counters + unseen-first draft bias,
   not name/flavor variation only.
7. Per-stage breakthrough triggers required in
   `progression_rules.md` (§2), grounding the GM's judgment.
8. Survival-trigger precedence: locked order
   (`bond_rescue` → `not_meant_to_die` → `last_barrier`); no
   other death-prevention slots.
9. `critical` is priority + visible danger, not a 1-turn death
   clock; consequence timing tracks the genre.
10. Two-layer textual HUD is part of the feature, not polish.
11. Save back-compat is not a goal during this dev phase.
