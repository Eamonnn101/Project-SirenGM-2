# CLAUDE.md — Operating schema for SirenGM 2

Read this before doing anything in this repo. Codex users: `AGENTS.md`
points here.

## The thesis

**AI compiles a novel into a playable world.** A user drops one or
more novels into `raw/novel/` (any genre; Chinese or English text
only), asks the agent to ingest them, and the agent produces one
user pack per novel under `packs/<pack>/`. The user then plays turns against a chosen pack
+ a save in `saves/<pack>/<save_id>/`, and the agent maintains both
the pack and the save over the course of the run.

We are validating: a 20–50-turn run against an ingested pack feels
coherent. We are NOT validating "play inside a prebuilt world." There is
no product-path demo pack; the main path is ingest.

## The operating layers

```
raw/novel/                 — immutable, user-provided source text (one file = one novel)
genre_packs/universal/     — shipped genre-agnostic template (style, guardrails, schemas, prompts)
packs/<pack>/              — AI-compiled wiki: novel_rules + characters, factions, locations, arcs, events
saves/<pack>/<save_id>/    — per-run canonical JSON state + rendered markdown, scoped to its pack
```

- **raw/** is never modified by the agent. Sources are immutable.
- **genre_packs/universal/** is the single shipped genre pack. It is
  genre-agnostic and language-agnostic — novel-specific rules live in
  each user pack's `novel_rules.md`.
- **packs/<pack>/** is written by the agent during ingest. Its
  `index.md` declares `language: <code>`; its `novel_rules.md`
  captures the novel's power system, social order, tech level, tone,
  and hard canon. Occasionally amended when play uncovers genuine
  contradictions.
- **saves/<pack>/<save_id>/** is written by the agent after every
  turn. Each pack owns its own save namespace, so multiple packs can
  coexist with independent `save_001`, `save_002`, … numbering.

The agent (Claude Code or Codex) is the runtime. There is no Python
process that drives the turn loop; the agent reads files, calls its
model, and writes files. A thin `tools/` layer provides deterministic
helpers (chunker, lint, render, inspect) but is optional.

## Canonical state rule

**Structured JSON is the source of truth.** Markdown surfaces in a save
are **re-rendered** from structured state at checkpoints. Ordinary
between-checkpoint turns may live in conversation temporarily, but any
checkpoint or immediate-trigger event must flush back to JSON before it
is treated as durable.

Canonical files in `saves/<pack>/<save_id>/`:
- `world_state.json` — must contain `current_location`, `present_entities`,
  `active_threads`, `current_objectives`, `risk_level`, plus `turn`, `day`,
  `time_of_day`, `flags`, `player`. Schema: `tools/_models.py::WorldState`.
- `relationship_state.json` — per-slug `{affinity, trust, status, last_interaction_turn, notes}`.
- `open_loops.json`
- `player.json` (mirror of `world_state.player`)
- `meta.json` (`save_id`, `pack_name`, `hidden_truths`). `save_id` holds only the
  short id (`save_001`); the pack is encoded in the directory path and mirrored
  in `pack_name`.
- `session_log.jsonl` — append-only authoritative turn record.
- `divergences.jsonl` — append-only record of dropped patches.

Rendered (non-authoritative) surfaces in `saves/<pack>/<save_id>/`:
- `current_scene.md`, `player.md`, `session_log.md`, `hidden_truths.md`.
- Regenerated by `python tools/render_save.py --save <pack>/<save_id>`
  at checkpoints, after the canonical JSON has been updated.

**If the narration and structured state disagree, structured state wins.**
Either promote the narrative fact into a structured field via the patch,
or drop it and append a `DivergenceNote`. Never silently accept narrative
facts into state.

**Scene context is derived from structured fields**, never by scraping
markdown. The agent looks up entities via `world_state.present_entities`
+ `current_location` + `active_threads`, not by matching slugs against
prose.

## Pack schema

### Genre pack (`genre_packs/universal/`)

One shipped pack, `universal`. Genre- and language-agnostic.

- `index.md` — frontmatter `name: universal`, `kind: genre`, `version`.
- `style_guide.md` — generic narrative conventions (POV, rhythm, no meta).
- `canon_guardrails.md` — generic world-consistency rules, player-agency
  counter-principle, default on/off for resurrection / time travel /
  cross-world travel.
- `systems/README.md` — placeholder; novel-specific mechanics live in
  the user pack's `novel_rules.md`.
- `schemas/*.schema.md` — frontmatter contracts for user-pack entity kinds.
- `prompts/*.md` — agent-facing instruction files for extract, draft, and
  narration.

**Forbidden** under genre packs: `characters/`, `factions/`, `locations/`,
`arcs/`, `events/`. The lint (`tools/lint_pack.py --genre universal`)
enforces this.

### User pack (`packs/<pack>/`)

The pack slug is derived from the novel's filename during ingest
(ASCII snake_case; see `playbooks/ingest.md` for the exact rule).

- `index.md` — frontmatter `name`, `kind: user`,
  `inherits_genre: universal`, `language: zh` or `language: en` (only
  these two are supported; rendering defaults to `zh` if unset).
- `novel_rules.md` — **load-bearing**; the novel's power/magic/tech
  system, social order, tone, hard canon. Read at play start/resume,
  after checkpoints, and when a turn triggers hard-canon judgment.
- `overview.md`, `canon_guardrails.md` (novel-specific overrides on top
  of the universal ones), `timeline.md`.
- `characters/<slug>.md`, `factions/<slug>.md`, `locations/<slug>.md`,
  `arcs/<slug>.md`, `events/<slug>.md`. Bodies are written in the
  pack's declared `language`; slugs remain ASCII snake_case.
- `relationships/relationship_matrix.md`.
- `contradictions/ambiguous_points.md`.
- `.ingest/` — chunker/extract checkpoints (`chunks.jsonl`, `mentions.jsonl`).

Entity frontmatter fields are defined by Pydantic models in
`tools/_models.py`. Any field named there is canonical; extras pass
through but don't participate in validation.

## Workflows

The agent follows these playbooks:

- `playbooks/ingest.md` — compile a novel into a pack (chunk → extract → draft → index → lint).
- `playbooks/new-game.md` — bootstrap a save from a pack.
- `playbooks/play-turn.md` — Core Play Kernel + checkpoint-based runtime
  (ordinary turns use active summary + private turn notes; checkpoints
  persist → render → lint).
- `playbooks/lint.md` — health checks.

The agent reads the relevant playbook at the start of the work.

## Tools

Optional, deterministic, offline. Never call an LLM.

| tool | when |
|---|---|
| `python tools/chunker.py <novel> --pack <pack>` | ingest, stage 1 |
| `python tools/lint_pack.py --pack <pack>` or `--genre universal` | after drafting pack pages; on demand |
| `python tools/render_save.py --save <pack>/<save_id>` | at checkpoints after JSON writes (load-bearing: keeps markdown in sync with JSON) |
| `python tools/lint_save.py --save <pack>/<save_id>` | at checkpoints, or before trusting a save for load / save/load continuity checks |
| `python tools/inspect_save.py --save <pack>/<save_id>` | on demand to summarize a save; add `--active-summary` to seed checkpoint runtime context |

The `--save` argument is resolved as `saves_root / <arg>`, so any path
under `saves/` works — use `<pack>/<save_id>` so multiple packs can
keep their own independent save numberings.

All tools have `--help`. See `tools/README.md`. Use `.venv/bin/python`
if your shell lacks a global `python`.

## One genre pack, many novels

`genre_packs/universal/` is the only genre pack the repo ships. Per-novel
differentiation happens at ingest time and is written into
`packs/<name>/novel_rules.md`, not by creating new genre packs. This
keeps the genre layer small and pushes all novel-specific judgment into
the ingest pipeline, where it belongs.

If a genuinely cross-novel mechanic emerges (e.g. a save-state
convention every novel must honor), add it to
`genre_packs/universal/systems/` or the universal prompts; do not
reintroduce per-genre packs.

## Local dev quirks

- macOS `hidden` flag on `.venv` files: if you do `uv pip install -e .`,
  run `chflags -R nohidden .venv` after — Python 3.10's `site.py` skips
  `.pth` files flagged hidden.
- Python 3.10+ for the tools. No other runtime is required.

## Things not to do

- Do not reintroduce a hand-authored product-path user pack. The main
  path is always ingest.
- Do not scrape markdown for scene state. The JSON files are canonical.
- Do not expand MVP scope without asking (per-genre packs, new CLI apps,
  web UI, combat formulas — all deferred).
- Do not hand-author a replacement for a user pack's `novel_rules.md` —
  the ingest pipeline synthesizes it.
- Do not let the GM drag the player back to preset arcs. `active_threads`
  and `current_objectives` are soft suggestions; the player's input wins.
  See `playbooks/play-turn.md` and the universal `gm_system_fragment.md`.
- Do not silently accept narrator facts the state patch cannot express.
  Drop them and log a `DivergenceNote`.
- Do not reinstate a Python CLI as the product path. If a helper is
  missing, add a new script under `tools/`, not a new CLI.
- Do not call `tools/` scripts on anything under `raw/` — those files
  are immutable input.
